- **2026-08-28** — Derangement-based exact permutation null added as rung 0's **final verification step**, closing the write-up caveat in `verification.md` ("the stratified null draws reuse the same half-profiles across mismatched pairs, so they are not exchangeable, while the bootstrap treats them as one"). Rather than argue that exposure further, `scripts/derangement_null.py` measures it directly — PROCESS §3's cheap-check principle ("a verification check that is cheap to compute is worth running... the argument convinces, the check settles"): it deranges the pairing between the two half-profile pivots (a permutation with no fixed points, so no draw can recover the correct match) and builds the null distribution of the mean mismatched correlation from `n_perm` such derangements directly, carrying the half-profile-sharing dependence by construction instead of assuming an exchangeable pool. The ratio of that derangement-null variance to the i.i.d.-pool bootstrap's assumed variance is the **design effect** the exchangeable-pool treatment ignores; its measured value is to be recorded in `verification.md` and `summary.md` once run on the real Tahoe pool. Reuses the measurement core (`build_split_half_frame`, `score_split_half`, `stratified_null_draws`, `masked_rowwise_pearson`) rather than reimplementing it, loaded the same way `tests/test_rung0_controls.py` loads it; known-answer tests in `tests/test_derangement_null.py` cover the derangement sampler itself (no fixed points, several sizes and seeds), a planted-signal recovery (p_exact < 0.05), a zero-signal negative control (p_exact > 0.01), and a design-effect sanity band ([0.2, 5.0]) on near-independent rows. Cluster job: `scripts/alpine/derangement_null.sbatch`, mirroring `delta_reproducibility.sbatch`'s structure.

- **2026-08-28** — Stratified derangement nulls added to `scripts/derangement_null.py`, in response to external review: the any-pair derangement above validates the pooled aggregate, but the promoted p-values are per-stratum (`p_vs_null` read against the `diff_drug` mismatched-pair pool, `p_vs_same_drug` against the `same_drug` pool, which clusters over ~32 drugs), and an any-pair derangement mixes both mismatch types freely, carrying neither stratum's dependence specifically. Two more permutations now carry each stratum's dependence by construction: `sample_within_drug_derangement` deranges each drug's rows among themselves (rows in a singleton drug group have no derangement and are excluded from the aggregate), matching the `same_drug` mask exactly; `sample_cross_derangement` repairs a random permutation, by repeated random-swap sweeps of violating positions, until every row's partner differs in both line and drug, matching the `diff_drug` mask exactly. `stratified_derangement_null` builds the two null distributions and their design effects the same way `derangement_null` does for the any-pair case, at each stratum's own row count and matching `stratified_null_draws` pool. Known-answer tests added to `tests/test_derangement_null.py`: sampler validity on fixtures with uneven drug-group sizes (including a singleton, which must be excluded) and on a fixture shaped like a real (line, drug) pivot index; an ordering control (planted drug-shared component, `_write_fixture_pool` with `drug_sd > 0`) showing the within-drug permutation-null mean sits above the cross permutation-null mean, since drug effects survive a within-drug mismatch but die across a cross mismatch; zero-signal and planted-signal controls mirroring the any-pair case, per stratum. Measured results on the real Tahoe pool are to be recorded in `verification.md` and `summary.md` once run.

- **2026-08-28** — **`spearman_brown`**: the plan's statistics section (Task 2) shows the Spearman-Brown lift computed inline as `2*r/(1+r)`; shipped `src/fmharness/statistics.py::spearman_brown` as a third, independently tested helper, consumed by `summarize()` (commit `5a4d038`) — so the lift is the same tested code wherever it is used, not reimplemented per call site.
- **2026-08-28** — **Null sampler `replace=False`**: plan:543 shows `rng.choice(..., replace=avail.size < n_perm)` (falls back to sampling with replacement once a stratum runs short); shipped samples without replacement whenever `avail.size >= n_perm` regardless (commit `9b24cc0`) — drawing the same mismatched pair twice would inflate apparent null precision without adding information.
- **2026-08-28** — **Column intersection in `score_split_half`**: plan:498 intersects only the pivot INDEX (patient, drug) across halves; shipped also intersects the pivot COLUMNS, i.e. the gene sets (commit `9b24cc0`) — `pivot_table` drops all-NaN columns per half independently, so two halves can carry different gene sets even after the row intersection, and a caller that skipped it could silently correlate misaligned genes.
- **2026-08-28** — **`clean_tree` redefinition**: plan:1100 shows plain `git status --porcelain`, captured after the result is copied into `results/`; shipped uses `--porcelain -uno` (tracked files only), captured BEFORE the copy (commit `441b238`) — untracked task-folder scratch sits in the working tree throughout this task, so counting it would make `clean_tree` permanently `False`, and capturing after the write would count the promotion's own output as a dirty-tree signal. This changes what the promoted record's `clean_tree` field means relative to the plan's text.
- **2026-08-28** — **Unverified-shard refusal in `register()`**: plan:1358 refuses only shards whose hash MISMATCHES a download-time etag; shipped also refuses shards with NO etag entry at all (commit `61060f3`) — an unlisted shard is not verified as unmodified, so silently registering it would be a weaker guarantee than the plan's text describes.
- **2026-08-28** — **`--input LABEL=PATH`**: plan:1122 shows `--input` taking a bare path (`type=Path`); shipped parses `LABEL=PATH` so the promoted record's `inputs` dict is keyed by a durable label rather than an ephemeral scratch path (commit `4211e30`) — already noted forward-looking in `verification.md`.
- **2026-08-28** — **`pyarrow>=15`**: the plan's Task 1 dependency block (`pyproject.toml`) lists `pydantic`, `numpy`, `pandas`, `duckdb`, `matplotlib`; the shipped `pyproject.toml` also carries `pyarrow>=15`, needed transitively for the parquet-writing path the fixture-based tests exercise — never added to the plan's text.
